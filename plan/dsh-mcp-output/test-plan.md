No new evaluator or fixture framework. Keep dummy token reference TEST_DSH_TOKEN only; do not use real credentials, user homes, services, browsers, or databases.

    run=$(mktemp -d /tmp/agent-env-dsh-delivery.XXXXXX)
    nix build .#example-dsh --out-link "$run/dsh"
    nix build .#example --out-link "$run/codex"
    nix develop --command bash tests/dsh-integration.sh "$run/dsh" "$run/codex"

The script creates mktemp directories outside the repository and isolated HOME/CODEX_HOME, exports TEST_DSH_PORT=18080, invokes the built /bin/agent-env apply --project "$project", and parses JSON/TOML using Python: DSH and Codex must have the same literal :18080 URL; DSH type=http; fetch command unchanged; cwd=$project. It invokes default opt-out apply on a second isolated project and checks absence of .dsh/mcp.json. It invokes DSH-enabled remove and checks its generated mcpServers are empty. The script is a focused extension of the repository's existing external shell integration approach, not a new test framework. Nix-dependent shell orchestration tests remain NOT RUN without their built AGENT_ENV_ACTIVATION_SCRIPT. Do not fake the installed environment or run activation inside a derivation.
