## 1. Purpose and authority

The user said “那我们先做一个单独的repo，用来合并上面两个东西，然后加上要我们自己做的东西”, approved private RekiDunois/agent-env-nix, and said “我来创建吧，你把代码准备好”. They also required: “话说，那些需要改config.toml的要怎么做？它不单要改，还得不影响现有的配置.” The user subsequently created the repository. This authorizes preparing this shared implementation, not migrating consumer repositories. The latest clarification is: “那没问题啊，改动应该是repo做的，.agents/skills里不应该直接改动。直接替换repo里的东西是正确做法”. Accordingly, owned selected skill trees are replaced from the producer without preserving edits inside that generated tree; unrelated skill trees and existing configuration still remain protected.

Build a small Nix library and one explicit project activation workflow. Each producer owns its files, business logic, native agent semantics, package split, and direct dependencies. Consumers select multiple root packages; explicit agent dependencies expand recursively. Skills must be complete ordinary files under the real project's .agents/skills/<name>, and native Codex agents ordinary .codex/agents/<name>.toml files. Selected MCP keys are safely merged into .codex/config.toml. Existing equal definitions may be reused without ownership; conflicting unowned definitions and edits to owned config/native-agent files are preserved and reported. Owned installed skill trees are generated artifacts, replaced as a whole from producer sources. Runtime paths are fixed Nix paths and the activated closure is GC-rooted.

Package-level enableHarnesses defaults to [ "codex" ] and supports callPackage/.override. Only Codex is implemented. [] disables a package's harness projection. Unknown harnesses fail explicitly. Existing producer APM/uv paths remain independent.

Non-goals: consumer migrations; producer business fixes; arbitrary APM/OpenCode conversion; other harness implementations; a registry, downloader, version solver, general module framework, global installation, Home Manager integration, secret manager, or new general testing framework. Project Consensus, Plan Reviewer Rule, and Test Engineer Rule retain their respective authority. API/state choices below are solution details, not new user requirements.

## 3. Frozen minimal interface and package identity

Export lib.mkAgentPackage and lib.mkProject, both taking pkgs. Producers normally return packages.<system>.<name> from callPackage; no duplicate agentModules output is required.

mkAgentPackage accepts: pkgs; id (stable producer/package identity); version; files (safe package-relative path to source file/tree); agentDependencies ? []; runtimePackages ? []; exports.skills ? {} (name to package-relative directory); exports.agents ? {} (name to { description; developer_instructions; }); mcp ? {}; mcpOverrides ? {}; enableHarnesses ? [ "codex" ]. Use lib.makeOverridable.

Return an ordinary derivation with passthru.agentEnv metadata. Put declared files beneath $out/payload, native artifacts beneath $out/codex/agents, and a small serialized manifest at $out/agent-env.json. The manifest contains actual store references to runtime packages and direct agent dependency payloads; passthru alone does not retain them. Reject unsafe/overlapping destinations, missing skill roots/SKILL.md, dangling or escaping source symlinks, and special files. Preserve complete directory contents, dotfiles, and executable bits. Materialize internal source-tree links; runtime store paths remain in fixed wrappers/configuration, not unresolved skill-tree symlinks.

The payload derivation identity excludes enableHarnesses: it controls projection selection, not business content. A change to files, agents, evaluated MCP settings, runtime references, or direct dependency payloads changes payload identity. version is descriptive and diagnostic, not version solving. Nix-ready command adaptation is producer-owned; this library does not rewrite uv/npm/Python instructions.

mkProject accepts pkgs, roots, name ? "agent-environment" and returns a derivation with desired artifacts, manifest, and bin/agent-env. It performs no project writes at evaluation/build time. Only agentDependencies are traversed. Same id + payload drvPath/output/system is one instance; repeated occurrences union normalized enableHarnesses. Thus [] and ["codex"] for the same payload become one Codex selection. Same id with different payloads fails with root-to-dependency paths. Detect cycles before serializing the recursive graph. runtimePackages need no agentEnv metadata and are never traversed for exports.

Collect each normalized package's own enabled exports. Different package identities exporting the same skill name, agent name, MCP key, or target path fail even if definitions are equal; never use last-wins aggregation. Empty roots is valid for removing this workflow's clean owned objects. One ownership state belongs to each canonical project directory.

## 4. Actual MCP integration and overrides

Evaluate each package separately with mcp-servers.lib.evalModule pkgs { imports = [ mcp mcpOverrides ]; settings.servers = {}; flavor = "codex"; format = "toml"; fileName = "agent-env-mcp.toml"; }. The explicit empty servers base makes packages without MCP valid. Force upstream assertions/configFile evaluation. Collect config.settings.servers and reject non-server extra settings so packages cannot inject unrelated model/provider/permission keys. Detect inter-package key conflicts before any module merge. Normalize each generic upstream record to the native Codex shape below, then generate final MCP-only TOML with upstream mkConfig using the normalized settings.servers and Codex flavor.

Normalization is required by [RawMcpServerConfig at the pinned Codex revision](https://github.com/openai/codex/blob/6fbd7be1518d259e30e6fef48f05f433d2461a20/codex-rs/core/config.schema.json): additionalProperties=false; native fields include http_headers/env_http_headers, but not generic headers/type; args and env values must be strings. The upstream named module emits headers={} and permits bool/int args/env, so flavor="codex" alone does not produce valid native records.

Initial accepted record keys are command, args, env, env_vars, cwd, url, headers, http_headers, env_http_headers, bearer_token_env_var, type, enabled, required, startup_timeout_sec, startup_timeout_ms, tool_timeout_sec, enabled_tools, disabled_tools. Reject other keys with a precise unsupported-field error, rather than silently discard them or claim the complete Codex schema is implemented. Validate command/url/cwd/bearer_token_env_var as nonempty strings where supplied; command is a fixed store executable. args/env_vars/enabled_tools/disabled_tools are lists of strings; env and header maps have string values; enabled/required are booleans; timeout values are nonnegative numbers, with startup_timeout_ms restricted to an integer. Reject simultaneous startup_timeout_ms and startup_timeout_sec rather than invent precedence. Do not coerce bool/int arguments or environment values.

Determine exactly one transport: command for stdio, url for HTTP. An absent type is inferred from that unambiguous choice; explicit type must agree. Accept stdio or http only, reject sse and mixed command/url. Remove type before generation. For HTTP, map nonempty headers to http_headers; if both are supplied require equal values, then keep one native field. Drop empty headers, args, and env defaults; reject nonempty args/env/env_vars/cwd on HTTP. For stdio, discard empty headers defaults but reject nonempty headers/http_headers/env_http_headers/bearer_token_env_var. Omit empty maps/lists used only as upstream transport defaults. This is a bounded adapter, not a new MCP framework.

Concrete override: package.override { mcpOverrides = { lib, ... }: { programs.fetch.package = myFixedFetchPackage; programs.fetch.args = lib.mkForce [ "--user-agent=Example" ]; }; }. This uses the actual upstream named-module override path. A custom producer server uses settings.servers.<name> = { command = <fixed-package>/bin/server; args = []; }; its command is changed through that setting or its producer argument, not through an unrelated programs option.

All executable commands resolve into the declared fixed closure. No runtime package installation. Secrets must not be literal values or readFile inputs in Nix declarations; runtime environment variables and producer-owned secret-reading wrappers stay outside the store. This initial library does not add credential storage or copy user .env files.

Transport normalization is explicit: for HTTP omit args, env, env_vars and cwd even when empty; for stdio omit http_headers and env_http_headers even when empty. Reject incompatible nonempty values before omission, rather than silently losing requested settings. This closes the transport-field boundary already identified in review, grounded in [Codex MCP transport validation](https://github.com/openai/codex/blob/6fbd7be1518d259e30e6fef48f05f433d2461a20/codex-rs/config/src/mcp_types.rs) (inspected blob c85e7c99b85f8e0b9bcf2a43d8de0c2a986699bd).

Existing update facilities were considered: Codex mcp add/remove and its configuration-write API target user configuration, not this project's file. Reuse upstream MCP TOML generation and the existing TOMLKit preserving editor for selected project keys; do not implement another TOML parser or general configuration framework.

## 5. Project activation and configuration preservation

Invoke bin/agent-env apply --project PATH, or bin/agent-env remove --project PATH. Resolve the actual project directory. Keep local state, staging, locks, and GC-root links in .agent-env-nix/, documented as untracked runtime data. No implicit shell hook, HOME writes, trust change, or force-takeover mode. A state-schema mismatch fails without guessing.

The initial adapter handles local file-based Codex configuration. Inspect selected keys in the target and ancestor .codex/config.toml files, CODEX_HOME/config.toml (default $HOME/.codex), and /etc/codex/config.toml when present on both Linux and Darwin, as the pinned [config loader source](https://github.com/openai/codex/blob/6fbd7be1518d259e30e6fef48f05f433d2461a20/codex-rs/config/src/loader/mod.rs) uses that path under cfg(unix). Report unavailable managed/MDM sources under the unsupported-source rule below. An --extra-config FILE option adds caller-known file sources and never removes automatic ones. Profiles/managed/cloud/session configuration not available to this file workflow is not claimed as validated; an explicitly detected unsupported selected source fails unchanged, while unknown future session -c overrides are outside activation's guarantee. Document this scope. Read global/parent sources only, never mutate them.

Check selected MCP tables and same-name agents.<name> declarations, including referenced role files. Check native agent declared names in applicable agent directories, not just filenames. Skill filesystem conflicts are limited to selected destination paths; no unrelated skill audit. Parsing a config file is necessary, but comparison and editing stay limited to selected keys.

Under a per-project lock, first stage all desired resources. Reuse upstream mkSyncProgram { mode="local"; allowOverrides=false; targets.codex={dest="skills"; structure="copy-tree";}; ...; } against a fresh private staging root via AGENT_SKILLS_ROOT. Do not run upstream --delete on .agents/skills. Strip only its staging ownership marker. Publish individual complete regular-file skill trees; generate native agent TOML with the pinned Nix TOML generator. Final skill/agent resources have no symlinks.

Use tomlkit from the Nix runtime closure to preserve existing TOML formatting/comments and unrelated/unknown settings. Only insert/update/remove selected mcp_servers.<name> tables. Do not replace config.toml with upstream-generated MCP TOML. Preflight the complete intended update before publishing: malformed/unreadable selected sources, unsafe paths, symlinked target/ancestor components, conflicting keys/names, or edited owned config/native-agent files fail clearly. Report package/export, key/path, and source without leaking secrets. No automatic destructive resolution; caller changes selection or resolves the source deliberately.

Ownership rules:
- Missing selected target/key: create and record its owner. Skills need root-level ownership, not per-file edit fingerprints. Native-agent files retain a last-written fingerprint; selected TOML keys retain their last-written values.
- Equal unowned target/key: reuse without rewrite or ownership. Equal inherited MCP/native-agent definitions avoid redundant project definitions. Unequal definitions elsewhere in the checked source set still conflict rather than silently masking them.
- Owned generated skill tree: replace/remove that complete selected tree regardless of edits inside it. Never extend ownership to its parent .agents/skills or to sibling trees. An owned path that became a symlink/unsafe object still fails path validation. Owned native-agent file or TOML key: update/remove only when equal to its last generated value; preserve/report user changes.
- Unselected/unowned content: leave it alone. Removal never deletes the containing config.toml, skill root, or agents directory; only recorded newly-created empty directories may be pruned.
- Equality for skill reuse covers the entire tree, contents, and executable bits; role equality uses parsed definition content; MCP equality includes meaningful unknown fields. Owned-native-agent edit detection compares the complete last-written file. No owned skill-content edit detection is required. A partial match is a conflict.
- Reused sources remain unowned after repeated apply/remove. If changed/missing later, next apply reassesses them rather than treating them as installer-owned.

## 6. Failure, concurrency, and runtime lifetime

State records package/export identities, owned skill roots, native-agent fingerprints/config values, reused sources, current environment output, and retained GC roots. Register the new environment output with nix-store --realise --add-root <fixed-project-state-root-path> --indirect before project artifact changes. The environment references selected packages, runtime packages, upstream configs, and staging program. Root registration failure stops activation. Do not move registered root links or run garbage collection.

Keep old roots until replacement succeeds; keep roots potentially referenced by preserved native-agent/config remnants. Remove only roots no longer needed by owned/preserved artifacts. Report retained roots instead of silently breaking edited scripts. Manual deletion/movement of the project/state is outside managed retention; document that a moved project needs reactivation to register new root locations before old roots are removed.

Use same-filesystem staging and atomic rename per file/tree/state file. Recheck selected content immediately before replacement. For config.toml, also retain the complete bytes/existence snapshot from which the new TOML was rendered and compare that whole snapshot immediately before replacement; any change, including an unrelated key/comment or creation/deletion, aborts that write without overwriting the newer file. A retry re-reads and re-renders from the current document. Selected-key checks alone are insufficient because publication replaces the file. Apply the same whole-file guard on removal. The lock serializes this tool, not arbitrary editors; this is an optimistic snapshot guard, not a claim of a filesystem-wide transaction. Record per-object pending old/new identities before writes; after interruption, retry only when observed content matches recorded old/new state, otherwise preserve/report. No all-project atomicity claim and no forced rollback over user edits. Normal preflight conflicts make no intended artifact changes; unexpected I/O failures report completed objects and keep needed roots for safe retry.

## 7. Ownership, alternatives, and invariants

Producers own business payload, native semantics, fixed wrappers, and dependency declarations. This repo owns graph normalization, upstream adapters, Codex rendering/merge, and activation lifecycle. Nix/upstreams own fetching/building/store tracking and their existing copy/MCP primitives. User/consumer owns root selection, overrides, credentials, external services, and conflict decisions. Fixtures/evaluators must not compensate for missing producer resources.

Causal chain: producer declarations → explicit dependency graph → complete staged native artifacts and fixed MCP commands → selected-key/conflict checks → copied owned project resources plus a real GC root. Direct upstream copying to the entire real .agents/skills root and whole-file MCP replacement is a realistic smaller alternative, but deletes unrelated skills/settings. Replacing only a selected owned skill tree is intended generated-artifact behavior, not an edit conflict. A new general distribution framework adds unnecessary ownership and scope; use the narrow adapter instead.

Representative invariants: diamond dependencies deploy once; mixed harness selections of the same payload do not conflict; runtime libraries do not export agent packages; complete support files survive copying; a different global selected MCP definition cannot be silently shadowed; equal unowned entries survive removal; owned generated skills are replaced as units while edited config/native-agent entries survive update; two producers cannot share one export name silently; copied store-path commands stay rooted; stale/pending state never authorizes unrelated deletion. These are design checks, not new test cases or evidence machinery.

Intended change: the new explicitly invoked Nix-to-Codex workflow. Preserved behavior: APM/uv and producer business behavior, unrelated project/global settings, secrets, and external services. Approved scope change: the shared repository rather than a business-producer helper. Prohibited effects: consumer migration, global writes, trust/security changes, runtime installs, broad cleanup, downstream bug fixes, and unneeded upstream code copies. No critical unresolved product impact is intentionally deferred; this new behavior still requires implementation and scoped validation.
